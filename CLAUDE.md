# Dofus diablo — notes pour Claude

- Répondre en français.
- `npm test` (vitest) et `npm run build` (tsc + vite) doivent passer avant chaque push.
- `src/sim/` ne doit jamais importer Phaser, `window` ni `Math.random()` : tout le hasard passe par `world.rng`.
- Multijoueur (maquette « Multi : », 2026-11-08) : la sim a une liste `world.players` ; `world.player` = le joueur qui agit pendant son pas, sinon le joueur de cet écran. Tout nouveau code de la sim doit marcher avec plusieurs joueurs (boucler sur `world.players`, ne pas supposer un seul perso ; un état propre à un joueur va dans `Player`, pas dans `World`). Coop : l'hôte fait la partie, l'invité recopie des instantanés (`src/sim/miroir.ts` : tout champ d'entité part sur le réseau ; un champ lourd ou propre au joueur va dans `REFUS`).
- L'affichage (`src/render/`) lit l'état et consomme `world.drainEvents()`, il ne modifie pas la partie.
- Le contenu (stats, sorts, vagues) est dans `src/data/*.json` ; l'apparence (planche, animations) dans `src/render/looks.ts`.
- Les monstres d'une zone sont ceux de sa sous-zone dans les données de Dofus 3 (choix de Mathis).
- Les animations de sorts sont les animations officielles (spellscripts -> casterAnimation), voir tools/extraction/LISEZMOI.md.
- Journal du jeu (`src/data/journal.json`, onglet Journal de l'accueil) : chaque PR ajoute une ou deux lignes, côté joueur, dans le carnet du jour (un carnet par date, rubriques Nouveautés / Le monde / Combat / Corrections / En coulisses). Nouveau jour = nouveau carnet avec titre, résumé et capture dans `public/assets/journal/<date>.webp`. Format lisible (vérifié par `tests/journal.test.ts`) : Nouveautés / Le monde / Combat = `{ titre (≤ 6 mots), phrase (≤ 110 caractères, une seule), details (≤ 2 phrases), icone (clé de `icones`), etiquettes (« Touche C », « Astrub », « Partie de test »…), image (option : « À la une », 3 au plus, `public/assets/journal/une/`) }` ; Corrections / En coulisses = une ligne de texte ≤ 110 caractères.
- Planches de monstres/PNJ/persos en AVIF (`FORMAT=AVIF`, trim_pack.py), le reste en WebP. Fichiers lourds (`.webp/.avif/.png/.jpg/.mp3` de `mondes/ sprites/ son/ fx/ cartes/`) : après tout export, lancer `node tools/hebergement/envoi.mjs` (empreintes `src/data/fichiers-lourds.json` + envoi sur Cloudflare R2), voir tools/hebergement/LISEZMOI.md. Les JSON restent dans le dépôt. Les fichiers lourds ne sont plus dans git : sur un clone neuf, `node tools/hebergement/envoi.mjs --recuperer` les reprend sur R2.
